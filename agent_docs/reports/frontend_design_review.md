## 2. Оценка

### Берём (как референс визуала)

- Стилистика «Своё Вино»: бордо-акцент, логотип `znak.png`, карточки со скруглениями, крупные CTA; mobile-first.
- Экран сканера: окно с «прицелом» (уголки) + подсказка + кнопки «снимок» / «выбрать фото».
- Карточка: производитель → название → теги (цвет, категория, регион) → сорт → описание. Поля совпадают с `wines` (`manufacturer`, `title`, `color`, `category`, `region`, `grape_variety`, `description`); дополнительно доступны `public_rating`, `dishes`, `alcohol_pct`, `serving_temperature`, `product_url`.
- «Исходное фото» + лайтбокс с зумом.
- Иконки бокалов (`img/glass_*`, `svg/public-rating*.svg`) для рейтинга.
- Чипы «Мясо / Рыба / Сыры» — ложатся на `wines.dishes`.

### Не берём

| Что | Почему |
|---|---|
| Клиентский YOLO (`detector.js`, `models/yolov8_label.onnx`, `onnxruntime-web` с CDN) | Stretch 640² и crop 256² stretch ≠ обучение (letterbox); другая модель, двойной кроп на сервере; 3 МБ на телефон. Оставить только статичный «прицел» |
| Окно «Мост к моделям (RTX 3090) / Cloudflare», `apiBase` в localStorage | Dev-инструмент; позволяет направить фронт на чужой сервер. Jinja = same-origin |
| Рейтинг из localStorage как «народный» | Фейк. Народный = `wines.public_rating` из каталога |
| Процент уверенности из `dino_similarity` / `sift_score` | Шкала не наша, SIFT нет. Заменить уровнем уверенности (§4.3) |
| `add.html` / `/api/products` | Вне скоупа (админка). Вместо — оценка результата поиска (§4.4) |
| Studio целиком, `/api/process_*`, `/api/detect/*`, `/api/twins/*` | Не входит в продукт |
| Вёрстка/CSS как код (inline `style=`, Google Fonts CDN, `via.placeholder.com`, `user-scalable=no`) | Прототип = только пример дизайна; верстаем заново |
| SPA-переключение `.view` через JS | С Jinja — отдельные страницы с URL; JS только для камеры/мелочей |

### Не хватает (требования ТЗ, `docs/notes_tz/new_spec_ideas.md`)

1. Состояние «не найдено в базе — рекомендуем аналоги» (сейчас `alert`, всегда `results[0]`).
2. Ссылка на страницу вина на сайте заказчика (`product_url`).
3. Кнопка «нашли то, что искали» / оценка соответствия.
4. Загрузка фото с устройства как равноправный путь (есть, но вторичный).
5. Подобие личного кабинета без сервера.

## 4. Целевая картина (вход для `contracts/web_ui.md`)

### 4.1 Страницы (Jinja2)

| URL | Назначение |
|---|---|
| `GET /` | Сканер: окно камеры с прицелом (`getUserMedia`, снимок полного кадра), кнопка «Загрузить фото» (`<input type=file accept=image/*>`); без JS — обычная форма |
| `POST /search` (form) | Принять фото → пайплайн → redirect на результат (PRG) |
| `GET /result/{search_id}` | Результат: `found` → карточка; `low` → карточка + «возможно, это не то» + аналоги; `not_found` → «не найдено в базе» + аналоги + подсказки OCR |
| `GET /wine/{slug}` | Карточка вина (из результата, истории, избранного, аналогов) |
| `GET /catalog?color=&grape=&…` | Выдача по фильтрам (аналоги / ручное уточнение) |
| `GET /me` | «Личный кабинет»: история, избранное, мои оценки — рендер из localStorage через JS |

### 4.2 JSON-эндпоинты, которые нужно запланировать в бэке

| Метод | Назначение | Примечание |
|---|---|---|
| `POST /api/v1/search` | Фото → `{search_id, status: found\|low\|not_found, confidence_level, winner?, candidates[≤5], ocr_hints{color?, grapes[], producer?}, analogs[]}` | Тот же пайплайн, что `/v1/eval/predict` (YOLO → SigLIP → pgvector → policy/OCR); eval-эндпоинт не меняется |
| `GET /api/v1/wines/{slug}` | Карточка | `public_rating`, `product_url`, `dishes`, … |
| `GET /api/v1/wines?color=&grape=&region=&category=&sweetness=&dish=&limit=` | Фильтр каталога (аналоги) | Индексы по фильтруемым полям — оценить |
| `GET /api/v1/dictionaries` | Справочники: цвета, сорта, регионы, категории, сладость, блюда | Сорта сейчас — текст `wines.grape_variety` (может быть бленд «А, Б»); нужен нормализованный список (distinct + split + алиасы из `ocr_rerank.yaml`) |
| `POST /api/v1/feedback` | `{search_id, slug, verdict: match\|mismatch}` | Хранение — см. вопрос Q1 |

`search_id` — серверный идентификатор результата (или подписанный токен), чтобы страница результата открывалась по URL без повторного инференса.

### 4.3 Уровень уверенности

`confidence_level ∈ {high, medium, low}` считает бэк из cosine top-1 (и margin) по порогам в конфиге; пороги калибруются вместе с `abs_min`. Фронт показывает только текст/бейдж, без процентов.

### 4.4 Оценка поиска

На странице результата: «Это то вино?» → **Да / Нет**. «Да» = «нашли то, что искали» (ТЗ). «Нет» → предложить аналоги / фильтры. Отправка в `POST /api/v1/feedback`; дублируется в локальную историю.

### 4.5 Аналоги из OCR

1. OCR-строки запроса (уже есть в пайплайне при rerank; для `not_found` / `low` — запускать OCR принудительно).
2. Извлечь: цвет (словарь: красное/белое/розовое/оранжевое + латиница), сорта (fuzzy по справочнику сортов + алиасы), производитель (по `manufacturer` каталога).
3. Сформировать фильтры → `GET /api/v1/wines?...` → 3–5 вариантов; показать найденные признаки чипами, чтобы пользователь мог снять/добавить фильтр.
4. Нет признаков → ближайшие по вектору из топ-5 (явно помечены «похожие по виду»).

### 4.6 Личный кабинет (без сервера)

- localStorage, ключи с префиксом `svoe_vino:`; версия схемы в ключе.
- История поисков: `{ts, slug?, status, confidence_level}` — **без фото** (размер, приватность); опционально маленькая превью в IndexedDB — решить.
- Избранное (`slug[]`), мои оценки (1–5 бокалов, локально, не смешивать с `public_rating`), мои отметки «соответствует/нет».
- Кнопка «Очистить мои данные».
- Демо-вход `user / user` (из notes_tz) — нужен ли, см. Q3.

### 4.7 Адаптивный дизайн

Прототип — только мобильная колонка (на десктопе растянутая/узкая карточка). Нужны два полноценных режима из одних шаблонов (CSS media queries, без отдельных десктоп-шаблонов):

| | Телефон (< ~768px, portrait) | Компьютер (≥ ~1024px) |
|---|---|---|
| Сетка | Одна колонка, full-width карточки | Контейнер ~1200px, 2 колонки |
| Сканер | Окно камеры на всю ширину, кнопки снизу (в зоне большого пальца) | Слева зона загрузки (drag&drop + «выбрать файл», камера — если есть веб-камера), справа подсказки / последние поиски |
| Результат | Фото над текстом, действия (Да/Нет, «на сайте») липкой панелью снизу | Фото слева, информация и действия справа; аналоги — сеткой 3–4 в ряд ниже |
| Каталог / аналоги | Список карточек, фильтры — выезжающая панель | Фильтры — боковая колонка слева, карточки — сетка |
| Меню | Нижняя таб-панель (Сканер · Каталог · Мои вина) **или** бургер — см. Q8 | Горизонтальное меню в шапке: логотип слева, пункты справа |
| Лайтбокс | Жесты (pinch/drag) | Колесо мыши + кнопки |

Промежуточный диапазон (планшет) — вариант телефона с 2-колоночной сеткой аналогов. Требования: без горизонтального скролла на 360px, зум страницы разрешён, touch-цели ≥ 44px, изображения `srcset`/`object-fit`, обе ориентации телефона не ломают вёрстку.

### 4.8 Прочее из прототипа

- «Цифровой сомелье», «Карта / найти в магазинах рядом», «Чат» — Этап 5; на MVP скрыть или неактивные заглушки (см. Q4).
- Камера через `getUserMedia` требует HTTPS на телефоне (кроме `localhost`) — для демо нужен туннель/сертификат; загрузка файла работает без HTTPS.

## 6. Зависимости от бэка

- SigLIP в проде (ветка `feat/siglip-prod`) — до финальной калибровки порогов.
- `abs_min` + пороги `confidence_level` (SIG-ABS-001) — фронт от них не зависит, берёт статус из ответа.
- Этап 3 (product API: §4.2) — фронт можно верстать на мок-JSON по контракту параллельно.
