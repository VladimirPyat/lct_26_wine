# OCR-реранк под SigLIP2: анализ и предложения

Дата: 2026-09-27. Контекст: `siglip2_embedding_results.md` (R@1 49/51, R@5 51/51 на кропах).
Статус: предложения для проработки (не реализовано).

## Текущее правило (прод)

`src/core/policy/decision.py` + `config/ocr_rerank.yaml`:

- OCR вызывается, если `margin = s1 − s2 < policy.margin_min` (**0.1**) и `enable_rerank: true`.
- `FuzzyReranker.rerank` пересортировывает топ-`min(rerank_top=10, top_k=5)` по `text_score`
  и **безусловно** берёт лидера по тексту как победителя.
- Порог 0.1 подбирался под DINO-base; у SigLIP другая шкала косинусов.

## Отрывы топ-1 у SigLIP (51 запрос, кропы)

- `s1 − s2` у верных топ-1: min 0.011, p10 0.036, **медиана 0.140**.
- Промахи: 0.037 (дубль SKU Alma Шардоне Резерв), 0.056 (Endemy Каберне красное vs розовое).
- Типичный паттерн низкого отрыва — **серийные близнецы**: 2–3 близких скора, затем резкий провал
  (например, `0.882 / 0.871 / 0.796 / 0.388`).

| `margin_min` | OCR на верных (из 49) | OCR на промахах (из 2) |
|---|---:|---:|
| 0.03 | 5 | 0 — промахи становятся «уверенными» |
| 0.05 | 7 | 1 |
| 0.06 | 8 | 2 — минимальный порог, покрывающий оба промаха |
| **0.07** | **11** | **2** |
| **0.08** | **13** | **2** |
| 0.10 (сейчас) | 15 | 2 |

Верные запросы в зоне OCR при 0.08 (все — близнецы серии): Alma Valley Graviti ×2, Ведерниковъ ×2,
Фанагория Cru Lermont, Бельбек, Chateau de Talu, Союз-Вино, Абрау Estates ×2, Aristov, Alma Valley
Темпранильо / Пино Нуар. Данные: `crop_score_gaps.json`.

**Вывод:** порог 0.07–0.08 (с запасом над 0.056) сокращает вызовы OCR, но в зоне остаются 11–13 верных
ответов при максимум 1 реально исправимом промахе (Endemy; Alma — дубль, текстом не решается).
При безусловной подмене победителя любой сбой fuzzy на близнецах сразу теряет R@1.

## Предложение: OCR как «вето с уверенностью», а не безусловная подмена

Идея: OCR запускается по порогу (как сейчас), но **меняет** image-победителя, только если текст даёт
**явного фаворита** в топ-5. Иначе остаётся топ-1 эмбеддингов.

Условия подмены (все настраиваемые):

1. `margin < margin_min` — триггер OCR (SigLIP: 0.07–0.08).
2. Текстовый лидер `T ≠` image-топ-1 `I`.
3. `text_score(T) − text_score(I) ≥ text_delta_min` — отрыв по тексту от текущего победителя.
4. `text_score(T) − text_score(второй по тексту) ≥ text_lead_min` — текст однозначен среди топ-5
   (у близнецов с общим названием серии текст часто «размазан»).
5. Опционально: `s_img(T) ≥ s1 − max_img_drop` — не тянуть снизу топ-5 кандидата, сильно проигрывающего
   по картинке (для SigLIP разумно ограничить ~0.06–0.08 = зона близнецов).
6. Опционально: `ocr_min_lines` / `ocr_min_chars` — при пустом/мусорном OCR не трогать решение.

`FuzzyReranker.rerank` уже возвращает `text_score` для каждого кандидата — условия 3–4 считаются
без изменения скоринга.

## Предлагаемые варианты в конфиге

```yaml
policy:
  top_k: 5
  margin_min: 0.08            # SigLIP; было 0.1 под DINO
  abs_min: 0.2                # перепроверить под шкалу SigLIP (s1 у верных: min 0.67, медиана 0.87)
  enable_rerank: true
  rerank_mode: confident      # off | always | confident
  confident:
    text_delta_min: ...       # подобрать на Dev (text_score(T) - text_score(I))
    text_lead_min: ...        # T vs второй по тексту
    max_img_drop: 0.08        # s1 - s_img(T) не больше
    ocr_min_chars: ...
```

- `off` — только эмбеддинги (текущий baseline SigLIP: R@1 49/51).
- `always` — текущее поведение (безусловная подмена лидером по тексту).
- `confident` — подмена только при явном текстовом фаворите.

Лог решения (`decision_log`) дополнить: `text_score` топ-5, `text_delta`, `text_lead`, причина отказа
от подмены — чтобы подбирать пороги по логам eval.

## План проверки (для следующего агента)

1. Прогнать PHOCR + `FuzzyReranker` offline на кропах всех 51 запросов (не только зоны OCR) с
   топ-5 SigLIP из `crop_score_gaps.json`; метаданные вин (title / manufacturer / category) — из БД
   или CSV каталога.
2. Для каждого запроса сохранить `text_score` топ-5 → таблица: сколько верных ломает `always`,
   сколько чинит; распределение `text_delta` / `text_lead` на «правильных» и «ложных» подменах.
3. Подобрать `text_delta_min` / `text_lead_min` так, чтобы **0 поломок** верных топ-1 на Dev-A,
   проверить на Dev-B (held-out).
4. Сравнить `off` / `always` / `confident` при `margin_min` ∈ {0.06, 0.07, 0.08, 0.10}.
5. Отдельно: учёт цвета (`красное` / `розовое` / `белое`) — вес `category` сейчас 0.15; кейс Endemy
   решается только им. Проверить, есть ли цвет в OCR-строках.

## Сопутствующее

- Дедупликация каталога (один SKU — несколько файлов) убирает класс промахов, который OCR не решает.
- Выборка мала: 1 запрос ≈ 2 п.п. Решение `confident` vs `off` лучше подтвердить на расширенном Dev.
