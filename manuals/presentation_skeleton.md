### Слайд 0.2 — Задача

Пользователь в магазине снимает этикетку → система находит **одну карточку** в каталоге (~2000 SKU) или предлагает **аналоги** и уровень уверенности.

**[Схема: телефон → ? → карточка вина]**

---

### Слайд 0.3 — Суть решения

**SigLIP2** (дообученные эмбеддинги) + **pgvector** top-K; при **низком отрыве** top-1 от top-2 — **OCR + fuzzy rerank** (`confident`, без слепой подмены).

**[Блок-схема: фото → YOLO → embed → top-5 → (?) OCR → slug]**

---

### Слайд 0.4 — Уникальность / «инновации»

ML-стек **классический** (detector + metric learning + vector DB + OCR rerank). **Главная ценность** — аккуратная **подготовка данных**: YOLO-кропы, phone↔catalog пары, near-разметка без утечек, eval только на hold-out.

**[Коллаж: market-пары / near_clusters / queries_crop — 3 мини-кадра]**

## Блок 2. Решение (~10 слайдов)

### Слайд 2.1 — Как обучали (данные)

Train: **phone-style aug** на каталоге + **реальные пары** «полка ↔ каталожное фото» (часто **вне owner-каталога**). Val / owner_eval — **не в train**. Индекс галереи — кропы каталога заказчика.

**[Таблица: catalog train / market pairs / dev_a,b — только eval]**

---

### Слайд 2.2 — Как обучали (модель)

**SigLIP2 so400m** + LoRA, **InfoNCE** (Phase 1). Сложные margin-loss **не дали прироста**; near-разметка помогла **гигиене split**, не magic loss.

**[График: кривая R@5 по эпохам Phase 1 — из `_logs` или схематично]**

### Слайд 2.3 — DINO → SigLIP (итог ML)

| | Hit@1 (51 запрос, кропы) | R@5 |
|--|--:|--:|
| **SigLIP2 FT, без OCR** | **49/51** | **100%** |
| DINO-L FT + OCR confident | 43/51 | высокий, но слабее top-1 |

До FT zero-shot **DINO** лучше мостил домен; после FT **SigLIP** — прод-энкодер.

**[Столбчатая диаграмма: SigLIP vs DINO+OCR]**

### Слайд 2.4 — Архитектура модулей

FastAPI: **runtime** (YOLO + SigLIP + OCR chain), **retrieve**, **policy**, **product/UI**. Postgres **pgvector**; decision log + feedback JSONL для аналитики.

### Слайд 2.5 — Точность (offline, как в сдаче)
