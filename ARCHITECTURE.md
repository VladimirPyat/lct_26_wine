# ARCHITECTURE — сканер вин «Своё Вино»

Фото этикетки → одна карточка вина из каталога «Своё Вино». Документ описывает пайплайн и границы слоёв. Детали модулей, логов и режимов policy — в [manuals/architecture.md](manuals/architecture.md), настройки — в [manuals/configuration_guide.md](manuals/configuration_guide.md).

**Статус (2026-09-28):** готовы каталог, поиск, eval-эндпоинт организатора и продуктовый API `/api/v1/*` (карточка + уверенность, аналоги, фильтры каталога, справочники, отзывы). Фронтенд — в работе (см. [тикет TZ-GAP-001](agent_docs/reports/ticket_tz_gap_001_remaining_scope.md)).

## Пайплайн

```
фото (multipart)
  │
  ▼
1. Нормализация фото     YOLO-кроп этикетки → letterbox 256 → mean/std 0.5
  │
  ▼
2. Извлечение признаков  SigLIP2 so400m (дообучен на винах, ONNX) → вектор 1152, L2
  │
  ▼
3. Поиск по каталогу     pgvector, косинус, top-5
  │                      отрыв s1−s2 < margin_min → OCR этикетки + fuzzy-переранжир
  ▼
4. Выдача                eval: {"slug": "..."}; продукт: карточка + found / low / not_found (/api/v1)
  │
  ▼
5. После поиска          аналоги (OCR-подсказки / фильтры победителя / вектор), фильтры каталога
```

## Слои

### 1. Нормализация фото

- **Кроп этикетки:** YOLO ONNX (`bin/yolo_detect_labels_2.onnx`) находит этикетку; кроп делается с исходника в полном разрешении. Выбор бокса учитывает уверенность, долю площади кадра и близость к центру (`select_label_box`).
- **Нет бокса** → берётся весь кадр, в лог решений пишется `used_fallback`.
- **Letterbox:** сторона 256 без искажения пропорций, поля заливаются средним цветом (123, 116, 103); нормализация mean/std 0.5 — ровно как при обучении энкодера (сверяется с `bin/*_preprocess.json`).
- Код: `src/core/cropper/`, `src/core/retrieve/preprocess.py`.

### 2. Извлечение признаков

- **Энкодер:** SigLIP2 so400m, дообученный на фото вин, экспорт в ONNX (`bin/siglip2_wine_p1_epoch_3.onnx`). Выход `pooler_output`, 1152, L2-нормировка.
- ONNX Runtime: CUDA при наличии GPU, иначе CPU (`compute.device`).
- Класс называется `DinoOnnxEncoder` по историческим причинам (до SigLIP2 был DINOv2); DINOv2-конфиг сохранён для отката.
- Код: `src/core/retrieve/dino_encoder.py`.

### 3. Поиск по каталогу

- **Хранилище:** PostgreSQL 16 + pgvector; таблица `wines`, колонка `embedding vector(1152)`.
- **Индекс каталога:** эмбеддинг YOLO-кропа эталонного фото; если кроп не удался — эмбеддинг полного фото. В `static/wines/{slug}.webp` лежит полная бутылка для интерфейса (то же фото, что в индексе).
- **Решение (policy):** top-5 по косинусу. Если отрыв первого от второго меньше `margin_min` (0.01), включается OCR этикетки (PHOCR или LLM) и fuzzy-сверка с производителем/сортом/брендом. В режиме `confident` текст меняет ответ только при сильном подтверждении (например, производитель + сорт).
- Зачем OCR: в каталоге есть вина с побайтно одинаковыми фото (30 групп); по картинке их не различить, по тексту этикетки — можно.
- Код: `src/core/retrieve/`, `src/core/policy/`, `src/core/ocr/`, `src/core/text/`, `src/db/`.

### 4. Выдача

- **Eval организатора:** `POST /v1/eval/predict` → всегда `{"slug": "..."}` (скрипт `data/owner_eval/*/participant_test.sh`). Score, отрыв, причина решения и задержки по этапам пишутся в JSONL-лог решений, не в ответ.
- **Продукт (готово):** `POST /api/v1/search` → карточка вина (производитель, регион, сорт, описание, рейтинг, к чему подать, `image_url`) + `score_1`, отрыв, уровень уверенности и top-5 кандидатов со score. Статус по порогам `config/product.yaml`: `found` (high / medium), `low`, `not_found` (без победителя, только аналоги) — сценарий «вина нет в каталоге». Фото и результат сохраняются на 10 дней по `search_id`. Тот же пайплайн, что у eval (`run_search`), поэтому ответы eval не меняются.
- Код: `src/api/`, `src/core/product/`.

### 5. Функции после поиска (готово)

- **Аналоги:** для `low` / `not_found` — по OCR-подсказкам этикетки (цвет, сорт); для найденного вина — тот же цвет и сорт из других виноделен; иначе — следующие кандидаты векторного поиска. До 5 вин по рейтингу + общее число.
- **Фильтры каталога** (`GET /api/v1/wines`: цвет, сорт, регион, сладость, блюдо) и справочники для них — основа сценария «крымское к шашлыку»; разбор свободного текста запроса в этот этап не входит.
- **Отзывы** «то / не то вино» → JSONL для калибровки порогов.
- LLM-слой: `src/llm/` (OpenAI-совместимый клиент, задачи в YAML).

## Границы слоёв

- Retriever (кроп → вектор → top-K) не вызывает OCR.
- Policy не знает про FastAPI и HTTP.
- PHOCR и LLM-OCR реализуют один интерфейс `IOCREngine`.
- API-слой только собирает зависимости (`src/api/runtime.py`) и отдаёт ответ.

## Каталог (офлайн)

```
data/owner_database/wines_integrated_updated.csv + images/{slug}.webp
  → prepare_clean_csv.py          CSV в схему импорта (строки без фото → rejected)
  → YOLO-кроп                     data/tmp/catalog_crops/ (+ review без кропа)
  → verify_catalog_assets.py      кроп и статика — одно и то же фото
  → catalog_import                SigLIP2 → pgvector; полная бутылка → static/wines/
```

Одной командой: `scripts/rebuild_catalog_db.sh` (см. [manuals/quickstart.md](manuals/quickstart.md)). Смена энкодера / размерности — миграция `0002_embedding_dim` + полный реимпорт.

## Метрики (публичные наборы `data/owner_eval/1`, `2`)

| | Значение |
|---|---|
| Угадано с первой попытки | 51 из 52 (set1 26/27, set2 25/25) |
| Время ответа | медиана ≈ 150 мс, максимум ≈ 1.9 с (первый запрос), SLA 3 с |
| Запуски OCR | только на почти полных ничьих (`margin_min` 0.01) |

Единственный промах — два вина Alma Valley «Шардоне Резерв» с одной этикеткой и разной крепостью.
